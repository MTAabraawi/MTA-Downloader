## In-app notices and license texts

- The app exposes an "التراخيص" destination in its navigation.
- The open-source license bundle contains upstream license texts for NewPipe Extractor, yt-dlp, yt-dlp-android, Chaquopy, CPython, and Certifi.
- The yt-dlp-android AAR contributes THIRD-PARTY-NOTICES.txt to merged app assets; the in-app screen reads and displays it.
- CI generates a CycloneDX aggregate SBOM before APK assembly, embeds it as open-source-licenses/DEPENDENCY_SBOM.json, and exposes it from the in-app licenses page.
- The app screen includes a source-repository link and the no-warranty / redistribution notice required for a prominent GPL legal-notice entry point.
- The root LICENSE, overlay, patch scripts, source archive, and pinned NewPipe source are assembled into the CI corresponding-source package. Do not publish a binary without the matching source offer/package.

## CI-generated compliance artifacts

The multi-engine workflow generates:
- CycloneDX aggregate JSON/XML SBOM from Gradle's resolved runtime dependency graph.
- Direct SBOMs for participating Gradle projects.
- Gradle dependency and dependency-insight reports.
- THIRD_PARTY_LICENSE_AUDIT.md, which checks component license metadata and scans APK/AAR contents for FFmpeg artifacts.
- A corresponding-source archive containing the MTA project source inputs, overlay and build/patch scripts, plus pinned NewPipe Extractor source.

The SBOM describes Gradle dependencies; it does not automatically enumerate Python distributions embedded inside an AAR. The audit script separately inspects Python .dist-info/METADATA entries when present. Any embedded package without a clear version/license remains an explicit manual review item.

## Release requirements

1. Keep the SBOM, license audit, full notices, and corresponding-source package with each release.
2. Resolve every NOT_REPORTED SBOM component and every embedded Python distribution with missing/ambiguous license metadata.
3. Confirm the exact yt-dlp, Certifi, Chaquopy, and CPython versions from the final AAR; retain corresponding upstream source and license texts.
4. NewPipe Extractor is GPL-3.0-or-later. Publish corresponding source and build/patch scripts alongside the app binary, and verify GPLv3 section 6 obligations for the complete distributed work. This notice is not a substitute for legal review.
5. If FFmpeg is added in the future, record its exact source revision, build flags, enabled codecs/libraries, LGPL/GPL/nonfree status, modifications, and corresponding source. FFmpeg's upstream default is LGPL-2.1-or-later, while optional GPL components change the applicable licensing; --enable-nonfree can produce an unredistributable build.
6. Do not distribute CI-signed APKs as production updates; preserve and verify the production signing key.

## Product constraints
